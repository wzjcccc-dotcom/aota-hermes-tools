# P11-L.1B — Completion-to-Origin Delivery Bridge

**Status:** Source-complete (outbox + safety protocol). Cross-process delivery
adapter ready but requires runtime design confirmation for actual
SessionChannel/SSE integration.

## Problem

After a Profile Task reaches terminal state, the finalizer durably writes:
1. Completion receipt (`completion.<start_id>.json`)
2. meta.json status update
3. Durable handoff (`handoff.<id>.json`)

There was **no bridge** to notify the originating Hermes WebUI session.
The origin session never learned the task completed unless it polled the
filesystem or relied on a separate `notify_on_complete` signal
(process-level only, no AOTA semantics).

## Solution — Outbox + Adapter

### Architecture

```
AOTA Worker Process                    WebUI Server Process
┌─────────────────────┐               ┌──────────────────────────┐
│ _profile_task_final │               │ _delivery_adapter        │
│            ize.py   │               │  .drain_pending_for_     │
│  ┌──────────┐       │  filesystem  │            session()     │
│  │receipt   │       │  ────────►   │  ┌────────────────────┐  │
│  │meta.json │       │              │  │list_pending_events │  │
│  │handoff   │───────┼──────────────┼──┤  _for_session()    │  │
│  │          │       │              │  └────────┬───────────┘  │
│  │_delivery │───────┼──────────────┼───►  deliver_one_event() │
│  │ _outbox  │       │              │  ┌────────┴───────────┐  │
│  └──────────┘       │              │  │SessionChannel.emit │  │
│                     │              │  │  → SSE → Browser   │  │
└─────────────────────┘              └──────────────────────────┘
```

### 1. `_delivery_outbox.py` (AOTA plugin, stdlib-only)

Producers a per-event **outbox file** on the AOTA filesystem after the
completion receipt, meta.json, and handoff are all durable.

- **Storage:** `<AOTA_RUNTIME_ROOT>/outbox/<workspace_id>/pending/<event_id>.json`
- **Atomic write:** temp sibling + os.replace (same pattern as handoffs)
- **Event ID:** `aota-task-terminal:<task_id>:<start_id>` — stable across reconciliation
- **Per-event state:** `pending/` → `delivered/` via atomic os.replace (rename)
- **Payload:** See schema V1 below — strictly sanitised, no raw data
- **Best-effort:** outbox write failure does NOT revert task terminal state
  or handoff

### 2. `_delivery_adapter.py` (AOTA plugin, designed for WebUI consumption)

Consumes pending outbox events and delivers them via Hermes SessionChannel.

- Lazily imports `background_process.get_session_channel` (safe off-WebUI)
- At-least-once: marks event `delivered/` only after `SessionChannel.emit()`
  reports success
- Per-event isolation: one failure does not block others
- SSE payload is a **trimmed subset** of the outbox event — no raw logs,
  no full reports

### 3. `_profile_task_finalize.py` changes

In the handoff-creation block, after `write_handoff_atomic` succeeds (or
existing handoff is found), loads `_delivery_outbox` via importlib and
calls `write_outbox_event(...)`.

## Event Payload Schema V1

```json
{
  "schema_version": 1,
  "event_id": "aota-task-terminal:pt_20260711T000000_abcdef01:pt_20260711T000000_abcdef01",
  "kind": "aota_task_terminal",
  "task_id": "pt_20260711T000000_abcdef01",
  "start_id": "pt_20260711T000000_abcdef01",
  "profile": "coder",
  "terminal_status": "done",
  "handoff_id": "ho_20260711T000000_01234567",
  "origin_session_id": "abc123def456",
  "summary": "task completed successfully; handoff=ho_20260711T000000_01234567",
  "needs_input_reason": null,
  "deliverable": true,
  "completed_at": "2026-07-11T00:00:00Z",
  "created_at": "2026-07-11T00:00:00Z"
}
```

**Explicitly excluded:** raw command, worker log, env vars, tokens/secrets,
full report content, SPEC.md, meta.json, completion receipt content.
