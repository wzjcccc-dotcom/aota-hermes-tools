# HOST-WI-03A1 Hermes Native Synthetic Parent Turn Reuse Assessment

This package is a read-only source reconnaissance at Hermes commit `689b51bef68f9ec95b638121bb9c7fefa3703fb2`.

## Decision

`MINIMAL_BACKEND_ADAPTER` / `PASS_MINIMAL_BACKEND_ADAPTER_REQUIRED`

Hermes does have a complete native completion-to-parent-turn path. The effective construction point is `GatewayRunner._inject_watch_notification`, with `gateway.wake.deliver_wake` as the reusable wrapper. Both feed the ordinary `MessageEvent` pipeline; the synthetic input is a `user`-role turn, enters the session history, runs normal prompt construction, can run tools and memory hooks, starts a new assistant generation, persists messages, and uses the normal stream/send path.

The path is not a standalone session-manager append API. Native durable delivery is coupled to `async_delegations`, `process_registry.completion_queue`, GatewayRunner ownership checks, the event loop, adapter registry, and profile-local session DB. AOTA Profile Task completion is generated by a separate `hermes -z` worker/finalizer process and currently ends at its sanitized filesystem outbox. Importability therefore does not imply runtime reuse.

The smallest safe future boundary is a trusted backend adapter that consumes only the AOTA sanitized outbox, validates parent profile/session ownership and canonical bounded pointers, applies event idempotency, then invokes the existing parent-backend wake path. Direct insertion into `async_delegations` is rejected as high risk because it would fabricate the native delegation lifecycle. Desktop frontend changes, runner changes, legacy overlays and full native delegation migration are not required by source evidence.

Evidence is under `deploy/evidence/host-migration/HOST-WI-03A1/20260726T131742Z/`; the latest pointer is `deploy/evidence/host-migration/HOST-WI-03A1/latest.json`. No live smoke, synthetic turn, task, delegation, Docker, database/runtime mutation, commit or push was performed.
